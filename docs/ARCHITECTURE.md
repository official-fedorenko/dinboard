# Архитектура

> Пометка **(планируется)** означает, что папки или модуля ещё нет. Всё без пометки уже создано.

## Структура папок
- `site/` — публикуемый сайт (только он попадает на GitHub Pages). Точка входа `site/index.html`.
- `site/css/` — стили (`style.css`: токены цветов, светлая и тёмная тема).
- `site/js/` — ES-модули приложения: `main.js`, `catalog.js`, `board.js`, `carriers.js`, `i18n.js`, `format.js`, `dom.js`, `render-svg.js`, `storage.js`, `checks.js`, `export.js`, `xlsx.js`, `enclosure-filter.js`, `ui.js`.
- `site/data/` — каталог оборудования в JSON: `index.json` (список брендов) и по файлу на бренд (`abb.json`, `eaton.json`, `hager.json`, `legrand.json`, `schneider.json`).
- `site/i18n/` — файлы переводов `ru.json`, `lt.json`, `en.json` (одинаковый набор ключей, проверяется тестом).
- `tests/` — тесты `node --test` (файлы `*.test.js`): сервер и файл запуска `start-dinboard.cmd`, `index.html`, workflow публикации, каталог (схема и настоящие данные), модель щита, переводы и подписи (включая сверку ключей кода с `ru.json`), раскладка и SVG-отрисовка щита, `dom.js`, сохранение (ссылка, файл, хранилище), проверки щита, выгрузки (спецификация, CSV, `.xlsx`), фильтры выбора корпуса.
- `tools/` — скрипты для разработки: `serve.js`, локальный сервер для `site/`.
- `docs/` — документация проекта (старые решённые записи — в `docs/ISSUES-archive.md`).
- `.github/workflows/` — `pages.yml`: тесты (Node 22 и 26) на каждый push и pull request, публикация `site/` на GitHub Pages только из `main` и только после тестов.

Файлы в корне: `package.json` (без зависимостей, только `"type": "module"`, `engines` и команды `npm start` / `npm test`), `start-dinboard.cmd` (запуск двойным кликом в Windows: открывает окно с `node toolsserve.js` и сайт в браузере по умолчанию; порт — `PORT` или 8080, сверяется тестом с `serve.js`), `.gitignore`, `.gitattributes` (переводы строк LF во всех текстовых файлах, у `*.cmd` — CRLF), `AGENTS.md`, `PLAN.md`.

## Как устроено
Сайт работает без сборки: браузер загружает `site/index.html`, а тот подключает `css/style.css` и `js/main.js` как ES-модуль. Все пути относительные, потому что на GitHub Pages сайт открывается из подпапки (`/<repo>/`).

Опубликованный сайт: https://official-fedorenko.github.io/dinboard/ (репозиторий `official-fedorenko/dinboard`, публикует `.github/workflows/pages.yml` при push в `main`).

`tools/serve.js` нужен только для локальной разработки: отдаёт файлы из `site/`, слушает только `127.0.0.1`, не выпускает запросы за пределы `site/`. Функции `resolveRequestPath`, `contentType` и `createSiteServer` экспортируются для тестов.

Модули в `site/js/` делятся на две группы.

Логика (без DOM, тестируется в Node):
- `catalog.js` — схема каталога, проверка (`validateIndex`, `validateBrandFile`, `validateCatalog`, `categorySchema`) и загрузка (`loadCatalog(baseUrl, fetchJson)`). Подробно — в разделе «Каталог».
- `board.js` — модель щита (чистые функции): `createBoard`, `addDevice`, `moveItem`, `removeItem`, `changeEnclosure`, `boardStats`, `billOfMaterials`. Щит: `{ version, enclosureId, rows: [[{ uid, deviceId, pos }]], nextUid, earthing }` (`earthing` — система заземления TN-S / TN-C-S / TT или `null`, `setEarthing`; сохраняется при смене корпуса и очистке щита; `carriers` — держатели клемм N/PE с клеммами (см. `carriers.js`): `createBoard` ставит их как с завода (`terminalSetup` корпуса), без комплектации — поля нет; `setCarriers`; пустой список — все убраны; при смене корпуса свои держатели остаются, если все они ставятся в новый корпус (`enclosureIds`) и среди них нет заводских шин другого корпуса, иначе — заводские нового корпуса; «в комплекте корпуса» пересчитывается по новому корпусу — `markFactory`). `clearDevices` — очистка щита: устройства и гребёнки убираются, система заземления и держатели клемм N/PE остаются. `combs` — гребёнки рядов ([id или null по рядам], без поля — нет; `setRowComb`); при смене корпуса остаются у существующих рядов. `combParts` — аксессуары гребёнок `{ id: количество }` (`setCombPart`, 0 — убрать); очистка щита снимает. Свободная расстановка: `pos` — с какого модуля рейки начинается устройство (шаг `POS_STEP` = 0.5), между устройствами могут быть пустые места, устройства не перекрываются, в массиве ряда — слева направо; вместимость ряда — `modulesPerRow` корпуса. Поиск места: `rowGaps` (свободные промежутки), `canPlace`, `firstFreePos` (куда ставит «+»), `nearestFreePos` (кнопки ← → ↑ ↓: шаг в сторону или через соседа до ближайшего свободного места), `snapPos` (перетаскивание: вплотную к соседу до половины модуля, иначе ближайший целый модуль), `dropPreview` (подсказка при перетаскивании: место как у `snapPos` и свободно ли оно). На занятое место — отказ: `BoardError('occupied')`; другие коды — `no-space` (нет свободного места нужной ширины подряд), `bad-pos`, `bad-row`, `unknown-item`, `unknown-device`. `changeEnclosure` оставляет устройства на своих местах, а не влезающие — на первое свободное место своего ряда, затем любого.
- `carriers.js` — держатели клемм N/PE (чистые функции, без DOM). Держатель щита: `{ carrierId, position: top | bottom, included, inserts: [{ insertId, pos (мм от левого края держателя), role? (N / PE — у универсальной шины, по крышке), included? }] }`. Места: `carrierGaps`, `canPlaceInsert`, `firstFreeInsertPos`, `snapInsertPos` (перетаскивание: вплотную к соседу или краю в пределах 5 мм, иначе шаг 0,5 мм). Действия: `addInsert`, `moveInsert`, `removeInsert`, `setInsertRole`, `setCarrierPosition`, `addCarrier`, `removeCarrier`, `swapCarrier` (подходящие клеммы переходят), `transferInsert` (клемма в другой держатель), `replaceInsert` (клемма — на другую того же держателя), отказ — `CarrierError` (`CARRIER_ERROR_CODES`: occupied, too-wide, bad-pos, unknown-insert, not-compatible, bad-carrier). Подсчёт: `carrierClamps` (клемм N и PE; общий блок N+PE — поровну), `clampNeed` (PE — по клемме на линию (автомат, дифавтомат), ввод и УЗИП; N делится по группам УЗО — у каждой группы своя шина N; группа — УЗО и автоматы правее него в том же ряду до следующего УЗО или рубильника; общая шина — ввод, входы УЗО, линии без УЗО, дифавтоматы, УЗИП с N), `railTerminals` (клеммники N/PE на DIN-рейку — тоже клеммы щита), `neutralBars` и `clampShortage` (чего не хватает: каждой группе — своя шина, общей — остальные вместе), `autoFill` (подбор по числу линий: для группы — отдельная шина N, иначе самая маленькая подходящая клемма, из подходящих — сначала подтверждённые; не хватает — самая большая и ещё; заводские остаются; `short` — сколько не хватает). Каталог: `carrierOptions` (держатели для корпуса), `addableCarriers` (что можно добавить или поставить на замену: держатель с артикулом или место под шину), `insertOptions` (клеммы для держателя, кроме частей заводских колодок), `factoryCarriers` (как с завода), `markFactory` (пометка «в комплекте корпуса» по комплектации корпуса: заводской держатель того же id, в нём — заводская клемма того же id; заводская клемма, перенесённая в другой держатель, — тоже с завода; при открытии проекта, смене корпуса и после каждого изменения держателей).
- `storage.js` — сохранение и загрузка. Проект: `{ enclosureId, rows: [[deviceId]], positions?: [[pos]], earthing?, combs?, combParts?, carriers? }` (`projectFromBoard` всегда пишет `positions`), обратно — `buildBoard` по каталогу: неизвестный корпус — `ProjectError('enclosure')`, неизвестные устройства пропускаются (`skipped`, соседи остаются на местах), устройство без позиции (старые ссылки и файлы) или с неподходящей позицией — на первое свободное место своего ряда, нехватка места — `ProjectError('no-space')`, неверный вид — `ProjectError('format')`. Форматы: ссылка `#b=<base64url JSON { v, e, d: словарь id, r: индексы, p?: позиции, g?: система заземления, k?: гребёнки рядов, x?: аксессуары гребёнок, n?: держатели клемм `[[carrierId, место, с завода 0|1, [[insertId, pos, роль|0, с завода 0|1]]]]` }>` (часть после `#` не уходит на сервер), файл проекта — читаемый JSON `{ app: "dinboard", version, savedAt, enclosure: { id, article }, earthing?, combs?, combParts?, carriers?, rows: [[{ id, article, pos? }]] }`; проект без `carriers` (старые ссылки и файлы) открывается с держателями как с завода, флаг `addTerminals` / `t` этапа 15 принимается, клеммники по нему не добавляются, а при открытии такого щита (без `carriers`) — подсказка подобрать клеммы заново (`buildBoard` → `oldTerminals`, сообщение `project.oldTerminals` в `restoreProject` и при открытии файла); держатели и клеммы не из каталога или не на своём месте пропускаются (`restoreCarriers`, в `skipped`), а «в комплекте корпуса» вычисляется по комплектации корпуса (`markFactory`), не по флагу в проекте — для этого `buildBoard` и `restoreProject` получают `catalog: { carriersById, insertsById }` (`pos` у всех устройств или ни у одного), хранилище браузера (`localStorage`, ключ `dinboard.project.v1`) — тот же JSON, что у файла; резервная копия прежней версии — `dinboard.project.v1.backup`. `restoreProject({ hash, localText, … , confirmLink })` — чистая функция выбора, что открыть при загрузке: щит, сообщения (ключи переводов) и `backupText` — текст, который нужно отложить в резервную копию, если сохранение урезано, не подходит к каталогу или заменяется щитом из ссылки. Щит из ссылки и сохранённый сравниваются в том виде, в каком их расставит каталог (старая ссылка без позиций на тот же щит — не замена); сохранение, теряющее при сборке устройства не из каталога, сравнивается как есть и всегда откладывается в копию. Лимиты размера, числа рядов и устройств, формат id проверяются; ошибки хранилища браузера (приватный режим) не ломают работу.
- `i18n.js` — `createTranslator(messages, fallback, lang)` → `t(key, params)` с подстановкой `{param}`, недостающие ключи берутся из русского словаря, `t.lang` — язык; `loadMessages(lang)` загружает `site/i18n/<lang>.json`; `pickLanguage(saved, browserLanguages)` — сохранённый выбор (`localStorage`, ключ `dinboard.lang`), иначе язык браузера (lt-LT → lt), иначе русский; `formatNumber(value, lang)` — числа по правилам языка (96,5 / 96.5); `placeholders(text)` — для теста переводов.
- `render-svg.js` — щит в SVG, вид спереди без дверцы, в миллиметрах: `layoutBoard` (рейка по центру корпуса, модуль 17.5 мм, ряды с шагом до 125 мм, видимая часть устройства 45 мм), `hitTest` (точка → ряд и `offset` — место на рейке в модулях; вне корпуса — `null`, перетаскивание отменяется), `slotRect` (прямоугольник места на рейке для подсказки при перетаскивании), `combBars` (гребёнки рядов: полоса над аппаратами ряда (в зазоре выреза) от первого до последнего аппарата, которые она соединяет — `COMB_DEVICE_CATEGORIES` из `catalog.js`), `carrierBars` (держатели клемм N/PE на рисунке: в настоящую длину по центру корпуса, у верхнего или нижнего края основания (`CARRIER_EDGE_MM` = 32 мм, как у Hager volta), несколько на одном месте — друг за другом от края к рядам, в низком корпусе — не заходя на полосу маркировки; цвет — из каталога (`color`); клеммы — в настоящую ширину от левого края держателя; без держателей — место пунктиром, если в корпус их можно поставить; в SVG клеммы — кнопки `data-carrier` / `data-insert`, цвет по роли, клеммы кружками, выделенная — с рамкой; чёрный держатель, белая колодка, место под шину — пунктиром), `renderBoardSvg` (строка SVG: корпус, лицевая панель с вырезами, полосы маркировки (10 мм) с номерами модулей 1…N (кегль 7.5 мм, как подписи устройств), номера рядов, заглушки на каждом свободном промежутке (`gaps` в раскладке) с делениями между модулями, устройства с рычажком, кнопкой «Т» у УЗО и дифавтоматов от 2 модулей, окошками индикаторов у УЗИП). Весь текст экранируется (`escapeXml`). Без DOM — покрыт тестами.
- `checks.js` — подсказки для монтажника (`checkBoard(board, enclosure, devices)` → `[{ level, key, params, deviceId? }]`, сначала предупреждения, потом советы; сборку не запрещают). Вводной аппарат (`mainApparatus`): рубильник, а без него — многополюсный автомат с наибольшим номиналом; фазность — по его полюсам. Проверки: нет вводного аппарата; нет УЗО/дифавтомата; УЗО меньше вводного; однофазный ввод и трёхфазные устройства; трёхфазный ввод и только однофазный УЗИП (без трёхфазного); УЗИП не подходит к системе заземления (по `specs.networks`; в TN-C-S принимаются УЗИП для TN-S) или система не указана; УЗО/дифавтоматы типа AC (совет: тип A); свободных мест меньше 20 %; держателя клемм N/PE и клеммников на рейке нет, а в корпус держатель можно поставить; клемм N или PE меньше, чем нужно (`clampNeed`), а при группах УЗО — шин N меньше, чем групп и общая, или в них мало клемм (`check.rcdNeutrals`); в совете о нехватке видно, из чего складывается «нужно» (`clampBasis`: линии, ввод, входы УЗО, УЗИП — ключи `check.part.*`, `CLAMP_PARTS`) (`checkBoard(…, combsById, carrierCatalog)`; клеммы, которые не помещаются или занимают одно место, в щит не попадают — это не даёт модель); гребёнки рядов (`checkBoard(…, combsById)`): другой производитель, серия не из списка производителя (`seriesMatch`: одна серия начинается с другой — iC60N / iC60), полюсов у аппарата больше, чем соединяет гребёнка, гребёнка короче занятого места. Схема соединений (какие автоматы за каким УЗО) не моделируется, поэтому проверки — эвристики.
- `export.js` — выгрузки спецификации: `specTable(board, enclosure, devices, brandNames, t)` → `{ head, rows }` (столбцы `SPEC_COLUMNS`: артикул, производитель, наименование, тип, ширина в модулях, количество, примечание «не проверено»; первой строкой корпус, затем устройства как в `billOfMaterials`; числа — числами), `toCsv(table, lang)` (BOM, строки через CRLF, для ru/lt разделитель `;` и десятичная запятая, для en — `,` и точка — так CSV открывается в Excel с настройками этой страны), `exportFileName(enclosure, ext)` (как у файла проекта), `combsSpec` и `combName` (гребёнки в составе: по рядам, одинаковые суммируются), `combPartsSpec` и `combPartName` (аксессуары гребёнок с количеством), `carriersSpec`, `carrierName`, `insertName` (держатели и клеммы N/PE: каждая деталь своей строкой сразу после корпуса, одинаковые суммируются; стоящие с завода — с примечанием «в комплекте корпуса»; места под шину — не деталь; `specTable(…, carrierCatalog)`), `clampsText`.
- `xlsx.js` — файл Excel без библиотек: `zip(files, date)` — zip без сжатия (CRC-32, дата в формате MS-DOS), `xlsxWorkbook({ sheet, head, rows }, date)` → `Uint8Array` — книга с одним листом из шести XML-частей (строки — `inlineStr`, числа — числовые ячейки, заголовок жирный и закреплён, ширина столбцов по тексту); `xmlText` (экранирование, удаление запрещённых в XML символов), `sheetName` (правила Excel для имени листа), `columnName`.
- `enclosure-filter.js` — фильтры при выборе корпуса (`ENCLOSURE_FILTERS`: производитель, монтаж, модулей в ряду, рядов; `'all'` — не задан): `filterEnclosures`, `availableValues(enclosures, filters, key)` — значения фильтра, с которыми вместе с остальными выбранными найдётся хотя бы один корпус (остальные в интерфейсе серые и не нажимаются, поэтому список никогда не пуст), `previewSplit(list, count, currentId)` — первые `PREVIEW_COUNT` (2) и остальные; если остался бы один — показываются все (окно ради одного корпуса не нужно); выбранный корпус, если подходит под фильтры, — первым.
- `format.js` — подписи из данных и переводов: `deviceTitle` («Автомат C16, 1P»), `deviceLabel` (короткая надпись на устройстве), `enclosureTitle`, `enclosureDescription`, `enclosureSize`.

Интерфейс (работает с DOM):
- `dom.js` — `h(tag, props, ...children)` создаёт элементы (строки — только как текст), `applyStyle` (CSS-переменные `--name` через `setProperty`; покрыт тестом на подставном объекте стиля).
- `main.js` — точка входа: выбирает язык и рисует переключатель RU / LT / EN в шапке (`#lang`; переключение без перезагрузки через `app.setTranslator`, выбор запоминается, фокус остаётся на выбранном языке; если перевод не загрузился — сообщение через `app.setStatus`), загружает переводы и каталог, убирает код щита из адреса, вызывает `restoreProject` (ссылка `#b=` — с подтверждением, если в браузере сохранён другой щит; иначе хранилище браузера), сохраняет резервную копию, если она нужна, и запускает `mountApp`; при ошибке показывает сообщение. Ставит `data-app-state` (`ready`/`error`) на `<html>`.
- `ui.js` — `mountApp(root, { catalog, t, store, initialBoard, initialStatus, backupText })`: корпуса фильтруются по производителю, монтажу, числу модулей в ряду и числу рядов (значения — из каталога; варианты, с которыми ничего не найдётся, серые и не нажимаются — `enclosure-filter.js`); показываются первые 2 подходящих корпуса (если подходит 3 — все три; выбранный корпус — первым), остальные — кнопкой «Ещё варианты (N)» (рядом — кнопка «Оставить текущий корпус», а у свёрнутого выбора — «Сменить корпус») в окне `<dialog>` (`showModal` после перерисовки, пока `state.moreOpen`; окно общее — `moreDialog`; Esc, ✕ и щелчок по подложке (точка вне прямоугольника окна) закрывают его и сразу сбрасывают состояние, не дожидаясь события close (в скрытой вкладке оно может не прийти), фокус возвращается на кнопку; выбор корпуса в окне закрывает его, отмена смены корпуса — нет; на телефоне окно во весь экран); список оборудования фильтруется по производителю (по умолчанию — бренд выбранного корпуса), категории и полюсам; в нём тоже видны первые 2 позиции (если подходит 3 — все), остальные — в окне «Ещё варианты» (добавление кнопкой «+», окно остаётся открытым, ответ — строкой в окне; перетаскивание — только из короткого списка); в составе щита указаны бренд и тип (`deviceRef`); под щитом блок «Проверки» (выбор системы заземления, блок «Клеммы N/PE»: сколько клемм N и PE и сколько нужно, кнопки «Подобрать по числу линий» и «Клеммы N/PE…» — окно `moreDialog` с держателями по очереди: место вверху/внизу, клеммы (крышка N/PE у универсальной шины, ✕), «Добавить клемму», «Заменить на …», «Убрать держатель», «Как с завода», «Добавить держатель» (заводскую колодку отдельно поставить нельзя); подсказки из `checks.js`); позиции с `verified: false` помечены «не проверено» в списке устройств, в карточке корпуса и в составе щита (с пояснением); после каждого изменения щит сохраняется в браузере; кнопки «Ссылка на щит» (в буфер обмена, иначе — окно с ссылкой), «Скачать файл проекта», «Открыть файл проекта» (с подтверждением замены), «Скачать прежнюю версию» и «Удалить прежнюю версию» (пока в браузере есть резервная копия — отложенная сейчас или раньше); панели «Корпус», «Щит», «Оборудование», «Состав щита»; под составом — «Выгрузка»: «Печать / PDF» (`window.print()`, перед печатью снимается выделение; перед любой печатью, в том числе по Ctrl+P, страница перерисовывается по событию `beforeprint`, чтобы дата и ссылка в шапке были свежими), «Скачать CSV», «Скачать Excel» (`export.js`, `xlsx.js`). Для печати в панели щита есть блок `.print-only` (корпус, дата, ссылка на щит); стили печати (`@media print` в `style.css`) прячут кнопки, фильтры, списки и подсказки, раскладывают панели в одну колонку и уменьшают высокий щит до листа; тёмная тема включается только на экране (`@media screen and (prefers-color-scheme: dark)`), поэтому печать всегда светлая. Состояние в одном объекте, после каждого действия всё перерисовывается (фокус восстанавливается по `data-focus`; если элемент исчез или недоступен — на запасной: перемещённое устройство, соседнее устройство или кнопку ряда). Данные выводятся только как текст. Щит выводится SVG из `render-svg.js` (строка разбирается `DOMParser` как XML, без `innerHTML`); над ним кнопки рядов «Ряд N · занято» и строка «Гребёнка ряда N» с кнопкой выбора (окно `moreDialog` с гребёнками производителя аппаратов ряда, «Без гребёнки» и аксессуарами гребёнок — количество кнопками − и +). Добавление: кнопка «+» (на первое свободное место выделенного ряда, если места нет — в первый ряд с местом) или перетаскивание из списка (HTML5 DnD, мышь; середина устройства — под указателем). Внутри щита: клик или Enter — выбор, перетаскивание в любое место рейки — Pointer Events (мышь и палец; на сенсорном экране — после выбора устройства касанием, тогда у рисунка `touch-action: none`); на занятое место — отказ с сообщением, устройство остаётся на месте. Во время перетаскивания (внутри щита и из списка) модули, которые займёт устройство, подсвечены: зелёным — свободно, красным — занято. Кнопки ← → (шаг на модуль или через соседа к ближайшему свободному месту; недоступны, если места нет) ↑ ↓ (в соседний ряд на ближайшее свободное место) ✕, Delete. Клеммы N/PE на рисунке: клик или Enter — выбор (панель: ← → на 5 мм, ↑ ↓ — держатель вверх или вниз, крышка N/PE, ✕, «Заменить на» — другая клемма того же держателя), перетаскивание вдоль своего держателя или на другой держатель (Pointer Events; подсказка места зелёным или красным, на занятое — отказ), стрелки ← → (с Shift — 0,5 мм), Delete; части заводской колодки не двигаются.

Связи (по плану): `main.js` загружает каталог (`catalog.js`) и переводы (`i18n.js`), создаёт модель (`board.js`), восстанавливает сборку (`storage.js`), передаёт модель в `ui.js` и `render-svg.js`.

## Каталог
Формат версии `schemaVersion: 1`. Проверка строгая: обязательные поля, допустимые значения, неизвестные поля запрещены (ловит опечатки); учитываются только собственные поля объектов, так что имена вроде `constructor` или `__proto__` не проходят. Тест `tests/catalog.test.js` проверяет и схему, и настоящие файлы в `site/data/`.

- `index.json`: `{ schemaVersion, brands: [{ id, name, file }] }`. `file` — только имя вида `brand.json` в той же папке.
- `<brand>.json`: `{ schemaVersion, brand: { id, name }, enclosures: [...], devices: [...], combs?: [...], combParts?: [...] }`.
- Аксессуары гребёнок (`combParts`, необязательно): `{ id, brand, series, article, model?, kind (end-cap — торцевая заглушка, feed-terminal — вводная клемма, tooth-cover — колпачки на свободные штыри), combSeries (серии гребёнок того же бренда), packQty?, verified, source?, notes? }`.
- Гребёнки (`combs`, необязательно): `{ id, brand, series, article, model?, phases (1P/1P+N/2P/3P/3P+N), pinType (pin — штырь, fork — вилка), lengthModules, pins?, cuttable?, crossSectionMm2?, ratedCurrentA?, deviceSeries? (серии аппаратов, как указал производитель), verified, source?, notes? }`. На рейку не ставятся — соединяют аппараты ряда поверх клемм.
- Держатели клемм N/PE (`terminalCarriers`, необязательно): `{ id, brand, kind (carrier — держатель, в который вставляются клеммы; plate — заводская колодка с неподвижными шинами; zone — штатное место корпуса под одну шину на своей опоре), series?, article?, lengthMm, positions (top / bottom), enclosureIds?, color? (black / white / grey — цвет на рисунке и в названии), verified, source?, notes? }`.
- Клеммы держателей (`terminalInserts`, необязательно): `{ id, brand, role (N / PE / N+PE / L / universal — роль задаёт крышка), series?, article?, clamps: [[число, мм²]], widthMm, color?, carrierIds?, fixed? (часть заводской колодки, отдельно не заказывается), verified, source?, notes? }`.
- Комплектация корпуса (`terminalSetup`, необязательно): `{ carriers: [{ carrierId, position?, included, inserts?: [{ insertId, pos, role?, included? }] }], verified, source?, notes? }` — что стоит с завода. `validateCatalog` сверяет ссылки (корпуса, держатели, клеммы) и что заводские клеммы помещаются и не перекрываются. Шины и клеммники на DIN-рейку — не часть корпуса (оборудование категории `terminal`).
- Общие поля позиций: `id` (уникален во всём каталоге, вида `hager-mbn116`), `brand`, `series`, `article` (артикул производителя), `model` (необязательно: тип у производителя, например `S201-C16` или `41P12X22`, если артикул — цифровой код), `verified` (проверено по официальному источнику), `source` (ссылка https на источник; обязательна при `verified: true`), `notes` (необязательно; служебная заметка для разработчиков на русском, в интерфейсе не показывается).
- Корпус (`enclosures`): `mounting` (`surface` — накладной, `flush` — встраиваемый), `rows`, `modulesPerRow`, `material` (`plastic`/`metal`), `door` (`transparent`/`opaque`/`none`), `ipRating` (число, например 41), `dimensionsMm` `{ width, height, depth }` (мм, допускаются дробные, например 96.5).
- Устройство (`devices`): `category`, `modules` (ширина в модулях, шаг 0.5), `specs` — набор полей зависит от категории:
  - `mcb` — автомат: `poles`, `ratedCurrentA`, `curve` (B/C/D), `breakingCapacityKa`;
  - `rcd` — УЗО: `poles` — только 2P или 4P (единое правило для всех брендов), `ratedCurrentA`, `sensitivityMa`, `rcdType` (AC/A/F/B);
  - `rcbo` — дифавтомат: поля `mcb` + `sensitivityMa`, `rcdType`;
  - `switch` — выключатель нагрузки: `poles`, `ratedCurrentA`;
  - `terminal` — клеммник (шина) N / PE на DIN-рейку: `role` (N / PE / N+PE), необязательно `clamps` ([[число, мм²]]), `ratedCurrentA`;
  - `distribution` — распределительный блок (кросс-модуль): `poles` (1P / 1P+N / 3P / 3P+N), необязательно `ratedCurrentA`, `clamps`;
  - `spd` — УЗИП: `poles`, `spdType` (1, 1+2, 1+2+3, 2, 2+3, 3), необязательно `networks` — системы заземления, для которых производитель указал применимость (`EARTHING_SYSTEMS`: TN-S, TN-C-S, TT); заполнено только там, где это указано в источнике.
- `poles`: `1P`, `1P+N`, `2P`, `3P`, `3P+N`, `4P`. У автоматов и дифавтоматов `4P` — защищены все 4 полюса, `3P+N` — защищены 3, нейтраль только отключается.

Сейчас в каталоге 5 брендов — 68 корпусов, 860 устройств (в т.ч. 25 клеммников N/PE и 28 распределительных блоков на DIN-рейку), 94 гребёнки, 13 держателей клемм N/PE и 72 клеммы к ним (у 52 корпусов указана комплектация с завода; у ABB — не выяснена) (непроверенных устройств 9, у каждого причина в `notes`). Автоматы — 1P, 1P+N, 2P, 3P, 3P+N, 4P с кривыми B, C, D; УЗО на 25–100 А, 10–300 мА, типы AC, A, F, B; дифавтоматы 1P+N, 3P+N, 4P; выключатели нагрузки 1P–4P до 125 А:
- ABB: корпуса Mistral41 (накладные 41P12X…, встраиваемые 41A12X…, 1–4 ряда по 12 мод.), S200 (S201–S204), F200, DS201, SD200, OVR;
- Eaton: корпуса xComfort BC-A (1–4 ряда по 13 мод., с дверцей и без), PL6, PF6, PFL6, PXF, PFIM, FRCdM, mRB6, IS, SPCT2/SPBT12;
- Hager: корпуса Volta с латунными шинами (VA..B, VU..NE) и с клеммами QuickConnect (VA..CN, VU..NC), 12 мод., MBN/MCN, NDN (кривая D), CD/CF/CDB (УЗО A, F, B), AD/AF, SBN, SPE/SPB/SPA;
- Legrand: корпуса Practibox S (накладные и встраиваемые, 12 и 18 мод.), DX3, DX3-ID, DX3 RCBO (1 и 2 мод.), DX3-IS, УЗИП 412xxx;
- Schneider Electric: корпуса Resi9 CX (1–4 ряда по 13 мод., без дверцы), iC60N, iID, iCV40N, iCV40H, iSW, iPRD/iQuick PRD/iPRD1.

Названия позиций в интерфейсе собираются из этих полей и переводов, поэтому в данных нет текстов на конкретном языке.

## Потоки данных
Работают все три потока.
1. Каталог: `site/data/*.json` → `catalog.js` (проверка) → списки корпусов и устройств в интерфейсе.
2. Сборка: действие пользователя в `ui.js` → изменение модели в `board.js` → перерисовка в `render-svg.js` → сохранение в localStorage через `storage.js`.
3. Восстановление: ссылка (URL) / файл проекта / localStorage → `storage.js` (проверка) → модель `board.js`.
