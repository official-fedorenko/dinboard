# Архитектура

> Пометка **(планируется)** означает, что папки или модуля ещё нет. Всё без пометки уже создано.

## Структура папок
- `site/` — публикуемый сайт (только он попадает на GitHub Pages). Точка входа `site/index.html`.
- `site/css/` — стили (`style.css`: токены цветов, светлая и тёмная тема).
- `site/js/` — ES-модули приложения: `main.js`, `catalog.js`, `board.js`, `i18n.js`, `format.js`, `dom.js`, `render-svg.js`, `storage.js`, `ui.js`.
- `site/data/` — каталог оборудования в JSON: `index.json` (список брендов) и по файлу на бренд (`hager.json`).
- `site/i18n/` — файлы переводов `ru.json`, `lt.json`, `en.json` (одинаковый набор ключей, проверяется тестом).
- `tests/` — тесты `node --test` (файлы `*.test.js`): сервер, `index.html`, workflow публикации, каталог (схема и настоящие данные), модель щита, переводы и подписи (включая сверку ключей кода с `ru.json`), раскладка и SVG-отрисовка щита, `dom.js`, сохранение (ссылка, файл, хранилище).
- `tools/` — скрипты для разработки: `serve.js`, локальный сервер для `site/`.
- `docs/` — документация проекта.
- `.github/workflows/` — `pages.yml`: тесты (Node 22 и 26) на каждый push и pull request, публикация `site/` на GitHub Pages только из `main` и только после тестов.

Файлы в корне: `package.json` (без зависимостей, только `"type": "module"`, `engines` и команды `npm start` / `npm test`), `.gitignore`, `.gitattributes` (переводы строк LF во всех текстовых файлах), `AGENTS.md`, `PLAN.md`.

## Как устроено
Сайт работает без сборки: браузер загружает `site/index.html`, а тот подключает `css/style.css` и `js/main.js` как ES-модуль. Все пути относительные, потому что на GitHub Pages сайт открывается из подпапки (`/<repo>/`).

Опубликованный сайт: https://official-fedorenko.github.io/dinboard/ (репозиторий `official-fedorenko/dinboard`, публикует `.github/workflows/pages.yml` при push в `main`).

`tools/serve.js` нужен только для локальной разработки: отдаёт файлы из `site/`, слушает только `127.0.0.1`, не выпускает запросы за пределы `site/`. Функции `resolveRequestPath`, `contentType` и `createSiteServer` экспортируются для тестов.

Модули в `site/js/` делятся на две группы.

Логика (без DOM, тестируется в Node):
- `catalog.js` — схема каталога, проверка (`validateIndex`, `validateBrandFile`, `validateCatalog`, `categorySchema`) и загрузка (`loadCatalog(baseUrl, fetchJson)`). Подробно — в разделе «Каталог».
- `board.js` — модель щита (чистые функции): `createBoard`, `addDevice`, `moveItem`, `removeItem`, `changeEnclosure`, `boardStats`, `billOfMaterials`. Щит: `{ version, enclosureId, rows: [[{ uid, deviceId }]], nextUid }`; устройства в ряду стоят подряд, вместимость ряда — `modulesPerRow` корпуса. Ошибки — `BoardError` с кодом (`no-space`, `bad-row`, `unknown-item`, `unknown-device`).
- `storage.js` — сохранение и загрузка. Проект: `{ enclosureId, rows: [[deviceId]] }` (`projectFromBoard`), обратно — `buildBoard` по каталогу: неизвестный корпус — `ProjectError('enclosure')`, неизвестные устройства пропускаются (`skipped`), нехватка места — `ProjectError('no-space')`, неверный вид — `ProjectError('format')`. Форматы: ссылка `#b=<base64url JSON { v, e, d: словарь id, r: индексы }>` (часть после `#` не уходит на сервер), файл проекта — читаемый JSON `{ app: "dinboard", version, savedAt, enclosure: { id, article }, rows: [[{ id, article }]] }`, хранилище браузера (`localStorage`, ключ `dinboard.project.v1`) — тот же JSON, что у файла; резервная копия прежней версии — `dinboard.project.v1.backup`. `restoreProject({ hash, localText, … , confirmLink })` — чистая функция выбора, что открыть при загрузке: щит, сообщения (ключи переводов) и `backupText` — текст, который нужно отложить в резервную копию, если сохранение урезано, не подходит к каталогу или заменяется щитом из ссылки. Лимиты размера, числа рядов и устройств, формат id проверяются; ошибки хранилища браузера (приватный режим) не ломают работу.
- `i18n.js` — `createTranslator(messages, fallback, lang)` → `t(key, params)` с подстановкой `{param}`, недостающие ключи берутся из русского словаря, `t.lang` — язык; `loadMessages(lang)` загружает `site/i18n/<lang>.json`; `pickLanguage(saved, browserLanguages)` — сохранённый выбор (`localStorage`, ключ `dinboard.lang`), иначе язык браузера (lt-LT → lt), иначе русский; `formatNumber(value, lang)` — числа по правилам языка (96,5 / 96.5); `placeholders(text)` — для теста переводов.
- `render-svg.js` — щит в SVG, вид спереди без дверцы, в миллиметрах: `layoutBoard` (рейка по центру корпуса, модуль 17.5 мм, ряды с шагом до 125 мм, видимая часть устройства 45 мм), `hitTest` (точка → ряд и позиция для перетаскивания; вне корпуса — `null`, перетаскивание отменяется), `renderBoardSvg` (строка SVG: корпус, лицевая панель с вырезами, полосы маркировки, номера рядов, заглушки на свободных местах, устройства с рычажком, кнопкой «Т» у УЗО и дифавтоматов от 2 модулей, окошками индикаторов у УЗИП). Весь текст экранируется (`escapeXml`). Без DOM — покрыт тестами.
- `format.js` — подписи из данных и переводов: `deviceTitle` («Автомат C16, 1P»), `deviceLabel` (короткая надпись на устройстве), `enclosureTitle`, `enclosureDescription`, `enclosureSize`.

Интерфейс (работает с DOM):
- `dom.js` — `h(tag, props, ...children)` создаёт элементы (строки — только как текст), `applyStyle` (CSS-переменные `--name` через `setProperty`; покрыт тестом на подставном объекте стиля).
- `main.js` — точка входа: выбирает язык и рисует переключатель RU / LT / EN в шапке (`#lang`; переключение без перезагрузки через `app.setTranslator`, выбор запоминается, фокус остаётся на выбранном языке; если перевод не загрузился — сообщение через `app.setStatus`), загружает переводы и каталог, убирает код щита из адреса, вызывает `restoreProject` (ссылка `#b=` — с подтверждением, если в браузере сохранён другой щит; иначе хранилище браузера), сохраняет резервную копию, если она нужна, и запускает `mountApp`; при ошибке показывает сообщение. Ставит `data-app-state` (`ready`/`error`) на `<html>`.
- `ui.js` — `mountApp(root, { catalog, t, store, initialBoard, initialStatus })`: после каждого изменения щит сохраняется в браузере; кнопки «Ссылка на щит» (в буфер обмена, иначе — окно с ссылкой), «Скачать файл проекта», «Открыть файл проекта» (с подтверждением замены), «Скачать прежнюю версию» и «Удалить прежнюю версию» (пока в браузере есть резервная копия — отложенная сейчас или раньше); панели «Корпус», «Щит», «Оборудование», «Состав щита». Состояние в одном объекте, после каждого действия всё перерисовывается (фокус восстанавливается по `data-focus`; если элемент исчез или недоступен — на запасной: перемещённое устройство, соседнее устройство или кнопку ряда). Данные выводятся только как текст. Щит выводится SVG из `render-svg.js` (строка разбирается `DOMParser` как XML, без `innerHTML`); над ним кнопки рядов «Ряд N · занято». Добавление: кнопка «+» (в выделенный ряд, если он полон — в первый ряд с местом) или перетаскивание из списка (HTML5 DnD, мышь). Внутри щита: клик или Enter — выбор, перетаскивание — Pointer Events (мышь и палец; на сенсорном экране — после выбора устройства касанием, тогда у рисунка `touch-action: none`), кнопки ← → ↑ ↓ ✕, Delete.

Связи (по плану): `main.js` загружает каталог (`catalog.js`) и переводы (`i18n.js`), создаёт модель (`board.js`), восстанавливает сборку (`storage.js`), передаёт модель в `ui.js` и `render-svg.js`.

## Каталог
Формат версии `schemaVersion: 1`. Проверка строгая: обязательные поля, допустимые значения, неизвестные поля запрещены (ловит опечатки); учитываются только собственные поля объектов, так что имена вроде `constructor` или `__proto__` не проходят. Тест `tests/catalog.test.js` проверяет и схему, и настоящие файлы в `site/data/`.

- `index.json`: `{ schemaVersion, brands: [{ id, name, file }] }`. `file` — только имя вида `brand.json` в той же папке.
- `<brand>.json`: `{ schemaVersion, brand: { id, name }, enclosures: [...], devices: [...] }`.
- Общие поля позиций: `id` (уникален во всём каталоге, вида `hager-mbn116`), `brand`, `series`, `article` (артикул производителя), `verified` (проверено по официальному источнику), `source` (ссылка https на источник; обязательна при `verified: true`), `notes` (необязательно; служебная заметка для разработчиков на русском, в интерфейсе не показывается).
- Корпус (`enclosures`): `mounting` (`surface` — накладной, `flush` — встраиваемый), `rows`, `modulesPerRow`, `material` (`plastic`/`metal`), `door` (`transparent`/`opaque`/`none`), `ipRating` (число, например 41), `dimensionsMm` `{ width, height, depth }` (мм, допускаются дробные, например 96.5).
- Устройство (`devices`): `category`, `modules` (ширина в модулях, шаг 0.5), `specs` — набор полей зависит от категории:
  - `mcb` — автомат: `poles`, `ratedCurrentA`, `curve` (B/C/D), `breakingCapacityKa`;
  - `rcd` — УЗО: `poles` (1P+N/2P/3P+N/4P, как у производителя), `ratedCurrentA`, `sensitivityMa`, `rcdType` (AC/A/F/B);
  - `rcbo` — дифавтомат: поля `mcb` + `sensitivityMa`, `rcdType`;
  - `switch` — выключатель нагрузки: `poles`, `ratedCurrentA`;
  - `spd` — УЗИП: `poles`, `spdType` (1, 1+2, 1+2+3, 2, 2+3, 3).
- `poles`: `1P`, `1P+N`, `2P`, `3P`, `3P+N`, `4P`.

Сейчас в каталоге Hager: корпуса Volta (накладные VA..B и встраиваемые VU..NE, 1–4 ряда по 12 модулей), автоматы MBN/MCN, УЗО CDA/CDC, дифавтоматы ADA/ADC, выключатели нагрузки SBN, УЗИП SPE/SPB/SPA — 8 корпусов и 62 устройства.

Названия позиций в интерфейсе собираются из этих полей и переводов, поэтому в данных нет текстов на конкретном языке.

## Потоки данных
Работают все три потока.
1. Каталог: `site/data/*.json` → `catalog.js` (проверка) → списки корпусов и устройств в интерфейсе.
2. Сборка: действие пользователя в `ui.js` → изменение модели в `board.js` → перерисовка в `render-svg.js` → сохранение в localStorage через `storage.js`.
3. Восстановление: ссылка (URL) / файл проекта / localStorage → `storage.js` (проверка) → модель `board.js`.
