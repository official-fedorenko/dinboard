# Правила ревью

## Режим

- Файлы проекта не менять. Исключение: записывать находки в `docs/ISSUES.md` (раздел «Замечания», пометка «Ревью» и серьёзность).
- Все находки, включая мелкие, записываются в `docs/ISSUES.md` сразу.

## Что проверять

- **Безопасность**: нет секретов в коде и коммитах; пользовательский ввод (в том числе данные из URL и `localStorage`) не вставляется в страницу как HTML без экранирования; внешние скрипты только из доверенных источников и с фиксированной версией.
- **Корректность**: логика подбора и расчётов (модули, номиналы, количество) соответствует описанию в `docs/PROJECT.md`; граничные случаи (пустой щит, переполнение по модулям, некорректные данные каталога).
- **Тесты**: новое поведение и исправленные ошибки покрыты тестами; тесты проходят командой из `docs/PROJECT.md`.
- **Соответствие проекту**: не используется ничего из раздела «Не используем» в `docs/PROJECT.md`; структура соответствует `docs/ARCHITECTURE.md`; соблюдены «Особенности проекта».
- **Поддерживаемость**: данные каталога отделены от кода; понятные имена; нет дублирования; изменения в рамках текущего этапа `PLAN.md`.

## Формат находок

Каждая находка:
- **Серьёзность**: критично / важно / мелочь.
- **Где**: файл и строка (или команда).
- **Проблема**: что не так.
- **Как проверить**: шаги или команда, которые показывают проблему.
- **Предложение**: как исправить.

Находки без места в проекте и способа проверки не включаются.
